# Theo Web workbench: source and license ledger

One row per component. A row is complete when lane, source and pin, author and license, and reference artifact hash are all filled. An incomplete row blocks that component's verify step.

Lanes:

- **verbatim**: source carried over with its tests, changed only at named seams. The row lists every change.
- **translation**: the source's mechanics re-expressed for Ratatui. The row reads "translated from", never "ported from".
- **library**: a published crate or package used as a dependency. No reference capture; the pin is the lockfile.
- **original**: nothing upstream models it. The row says why.

Reference artifacts live under `docs/plans/evidence/refs/` and are named `<component>@<pin>.png`. "pending" means the capture is the first step of that component's work order.

Not adopted, and why: `edtui` (modal editor, hard `crossterm` and clipboard dependencies); `syntect` (a second highlighter beside the one already in use); Codex `markdown_render.rs` and `diff_render.rs` (3,353 and 2,745 lines bound to terminal color detection and an older `pulldown-cmark`, where existing code already draws both); `ratatui-textarea` 0.9.4 (planned at Gate 0, rejected in Gate 3 after a probe: its history is private and positional so one remote edit clears undo, it has no edit-at-range without moving the cursor, no atomic ranges, a `char`-counting cursor that stops inside grapheme clusters, per-character undo, it loses CRLF, and it emits no change deltas); `wezterm-input-types` (keys only: no mouse, focus or paste encoding, and three further dependencies); `alacritty_terminal` and `termwiz` (neither is an input encoder that fits beside `vt100`); `egui_dock`, `egui_tiles` and `grimdock` (docking for other toolkits, none for Ratatui).
